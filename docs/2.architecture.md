# 2. 架构总览

## 2.1 入口：main.cpp

```cpp
void setup() {
    EASYB.init();                              // 框架初始化
    EASYB.servicesRtos.xxxServiceRtos.rtosRun();  // 按需启动服务
}

void loop() {
    vTaskDelay(portMAX_DELAY);                 // 不再使用 Arduino loop
}
```

`main.cpp` 只做两件事：**初始化 EasyBoard**、**选择并启动需要的服务**。

我们不推荐在 `loop()` 中编写业务逻辑。ESP32 是多核芯片，框架基于 FreeRTOS 将每个功能模块拆成一个独立 task——这就是「服务」。每个服务拥有自己的栈空间、运行周期和生命周期钩子，互不阻塞。如果你确实有需要在单线程上下文中运行的代码，写在 `loop()` 里也是可以的，但那是例外而非推荐做法。

## 2.2 EasyBoard：唯一的中央枢纽

一切设备和服务的访问入口只有一个：

```cpp
#define EASYB EasyBoard::instance()
```

`EASYB` 是全局可用的板级单例，它**独占**以下资源：

```
EASYB
(EasyBoard)
  ├─ 总线 ──────────────────────────────────────┐
  │   spiH  (HSPI, 唯一 new SPIClass 处)         │
  │   spiF  (FSPI, 未接线时为 nullptr)           │
  │   i2c0  (= &Wire, 唯一 Wire.begin() 处)      │
  │                                              │
  ├─ GPIO 管理 ──────────────────────────────────┤
  │   pinsAlloc[32]   引脚冲突注册表              │
  │   bootGPIO()      注册占用                    │
  │   unbootGPIO()    释放占用                    │
  │   dumpPins()      打印占用表                  │
  │                                              │
  ├─ 设备 (按总线分组) ──────────────────────────┤
  │   devicesGpio                                │
  │     ├─ mic          (INMP441 麦克风)          │
  │     ├─ spk          (MAX98357 喇叭)           │
  │     ├─ tb6612Wheels (TB6612 电机驱动)         │
  │     │   ├─ motor1   (N20 电机 1)              │
  │     │   └─ motor2   (N20 电机 2)              │
  │   devicesI2c                                 │
  │     └─ oled         (SSD1306)                │
  │   devicesSpi                                 │
  │     ├─ lcdNv3007    (NV3007 LCD #1)          │
  │     └─ lcdNv3007_2  (NV3007 LCD #2)          │
  │   wifi              (ESP32 WiFi, 独立实例)    │
  │                                              │
  ├─ 服务 (值成员, 直接 .rtosRun()) ─────────────┤
  │   servicesRtos                               │
  │     ├─ voiceEchoServiceRtos                  │
  │     ├─ connectivityServiceRtos               │
  │     ├─ motionServiceRtos                     │
  │     └─ displayServiceRtos                    │
  │                                              │
  ├─ chipWebServerRtos    (Web 服务, WiFi 自动启停) │
  ├─ chipSqlite           (LittleFS 上的 SQLite)  │
  └─ neoPixel             (板载 WS2812 LED)       │
```

### 2.2.1 总线唯一入口

- **I2C**：`Wire.begin()` 只在 `EasyBoard::initI2c()` 里调用一次。设备通过 `EASYB.i2c0` 获取总线指针，禁止自行 `Wire.begin()`。
- **SPI**：`new SPIClass` 只在 `EasyBoard::initSpi()` 里调用。设备通过 `EASYB.spiH` / `EASYB.spiF` 获取总线指针。

这是铁律——违反会导致多实例冲突、总线状态不一致。

## 2.3 设备：应该由谁持有

设备按通信总线分目录存放：

```
src/device/
├── gpio/     # DeviceGpioBase 子类：麦克风、喇叭、电机驱动、编码电机
├── i2c/      # DeviceI2cBase 子类：OLED 等
├── spi/      # DeviceSpiBase 子类：LCD 显示屏
└── Wifi.*    # DeviceBase 直接子类：WiFi（芯片内置外设，不挂总线）
```

### 2.3.1 设备的归属规则

| 层级 | 角色 |
|---|---|
| **EasyBoard** | 持有所有设备实例（`devicesGpio` / `devicesI2c` / `devicesSpi` 结构体）。设备在 `instance()` 工厂里创建，但此时不做硬件初始化。 |
| **Service** | 在 `_rtosBegin()` 里 `device->boot(serviceName)` 激活设备，在 `_rtosEnd()` 里 `unboot(serviceName)` 释放。 |

- 设备**不直接**被 main.cpp 操作——所有硬件操作必须通过服务完成。
- 设备**可以**被多个服务共享：boot/unboot 基于引用计数，首个 boot 做硬件初始化，末个 unboot 才释放。

### 2.3.2 总线基础类的 boot 差异

| 基类 | boot() 自动做的事 |
|---|---|
| `DeviceGpioBase` | 遍历子类的 `PIN_GPIOS` 向 EasyBoard 注册引脚（需先 `setEasyBoard(this)` 注入） |
| `DeviceI2cBase` | 调用子类 `initI2c()` 获取总线 |
| `DeviceSpiBase` | 注册引脚 + 置 OUTPUT/HIGH，再调子类 `initSpi()` 获取总线 |

## 2.4 服务：应该由谁持有

服务按功能分文件存放：

```
src/service.rtos/
├── Connectivity.service.rtos.{h,cpp}
├── Display.service.rtos.{h,cpp}
├── Motion.service.rtos.{h,cpp}
└── VoiceEcho.service.rtos.{h,cpp}
```

每个服务 = 一个 `RtosBase` 子类 = 一个 FreeRTOS task。

### 2.4.1 服务的归属规则

| 层级 | 角色 |
|---|---|
| **EasyBoard** | 持有所有服务实例（`servicesRtos` 结构体，值成员，非指针）。 |
| **main.cpp** | 通过 `EASYB.servicesRtos.xxx.rtosRun()` 启动服务，通过 `rtosStop()` 停止。 |

### 2.4.2 服务生命周期

```
rtosRun()   ─→  initRtos()      // 子类设置 task 名称、栈大小、循环间隔
            ─→  _rtosBegin()     // 主线程执行：boot 设备、申请资源（⚠ 不能 delay）
            ─→  xTaskCreate()    // 创建 FreeRTOS task
                ─→  _rtosBeforeLoopOnce()   // 一次性预热逻辑（可以 delay）
                ─→  while(running) { _rtosLoop(); vTaskDelay(间隔); }
                ─→  _rtosEnd()   // 清理：unboot 设备、释放资源
                ─→  vTaskDelete()
```

## 2.5 架构设计原则

1. **框架持有、服务使用**：设备实例和服务实例都由 EasyBoard 统一持有，服务和设备之间通过 boot/unboot 建立临时的使用关系。
2. **设备不主动，服务来驱动**：设备只暴露硬件能力（读、写、动作），服务的 `_rtosLoop` 编排调用时序。
3. **总线由框架独有**：任何地方不自行创建 SPI/I2C 实例，只从 EasyBoard 取用。
4. **main.cpp 极简化**：它只是启动清单，所有逻辑下沉到服务中。
