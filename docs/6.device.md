# 6. 设备

设备是对物理外设的软件抽象，封装了引脚配置、通信协议和硬件操作。所有设备最终继承自 `DeviceBase`，按总线类型分为 GPIO、I2C、SPI 三大类。

## 6.1 DeviceBase：所有设备的根

### 属性

| 属性 | 类型 | 说明 |
|---|---|---|
| `deviceName` | `const char*` | 设备名，用于日志和冲突表标识 |
| `booted` | `bool` | 是否有服务正在使用该设备 |
| `bootServices` | `vector<const char*>` | 当前持有者列表（按 serviceName 去重） |
| `PIN_GPIOS` | `struct Pins` | 引脚声明，子类覆写，基类通过 `begin()`/`end()` 遍历 |
| `_MULTI_INSTANCE` | `static constexpr bool` | 单例（false）还是多实例（true） |

### 方法

| 方法 | 说明 |
|---|---|
| `static instance(...)` | 工厂方法，只赋值属性，不做硬件初始化 |
| `boot(serviceName)` | 申请使用设备，返回 `true` 表示这是首个持有者 |
| `unboot(serviceName)` | 释放设备，全部持有者释放后才关闭硬件 |
| `setEasyBoard(board)` | 注入 EasyBoard 指针（GPIO 设备必需） |

### 6.1.1 boot / unboot 引用计数

```cpp
bool boot(const char* serviceName);   // 返回 true 仅当这是第一个持有者
void unboot(const char* serviceName); // 移除持有者，全部释放后才关闭硬件
```

多个服务可以 boot 同一设备，框架按 `serviceName` 去重追踪。首个 boot 做硬件初始化，末个 unboot 才释放。

```
[BOOT]   Lcd.NV3007 <- 'display'  (wasBooting=0, bootCount=1)   ← 硬件初始化
[BOOT]   Lcd.NV3007 <- 'another'  (wasBooting=1, bootCount=2)   ← 仅计数 +1
[UNBOOT] Lcd.NV3007  (remaining=1)
[UNBOOT] Lcd.NV3007  (remaining=0)                               ← 真正释放硬件
```

### 6.1.2 _MULTI_INSTANCE：单例还是多实例

决定 `instance()` 如何创建设备实例：

- **`false`（单例）**：芯片上只可能有一个此设备。`instance()` 返回函数内 `static` 局部变量，全局唯一。例如麦克风、喇叭、TB6612、SSD1306。
- **`true`（多实例）**：芯片上可能有多个同型设备。`instance()` 每次 `new` 一个新对象。例如 LCD 双屏、多路 N20 电机。

`instance()` 只赋值 `deviceName` 和引脚等属性，硬件初始化统一在 `boot()` 中进行。

### 6.1.3 PIN_GPIOS：引脚声明

设备的所有 GPIO 引脚写在嵌套 struct 中，基类通过 `begin()` / `end()` 遍历：

```cpp
struct Pins {
    PinDef cs  {"Lcd.NV3007.CS",  GPIO_NUM_NC};
    PinDef dc  {"Lcd.NV3007.DC",  GPIO_NUM_NC};
    PinDef* begin() { return &cs; }
    PinDef* end()   { return &dc + 1; }
} PIN_GPIOS;
```

- `PinDef.owner` 用于 GPIO 冲突日志
- 未接线引脚用 `GPIO_NUM_NC`，框架自动跳过

### 6.1.4 新增设备

以新增一个 I2C 传感器 `Foo.Bar` 为例：

**1. 添加引脚宏**（`config/pinGpios.config.h`）：

```cpp
#define PIN_GPIO_FOO_BAR_SDA GPIO_NUM_10
#define PIN_GPIO_FOO_BAR_SCL GPIO_NUM_11
```

I2C 设备如果走框架总线（`EASYB.i2c0`），则无需额外引脚宏，只需 I2C 地址。

**2. 写头文件**（`src/device/i2c/Foo.Bar.i2c.device.h`）：

```cpp
#pragma once
#include "core/base/DeviceBase.i2c.h"      // 只 include 基类，不 include EasyBoard.h
#include <Wire.h>

class FooBarI2cDevice : public DeviceI2cBase<FooBarI2cDevice, TwoWire> {
   public:
    struct Pins {                          // 如不走 GPIO 可为空
        PinDef* begin() { return nullptr; }
        PinDef* end()   { return nullptr; }
    } PIN_GPIOS;

    static FooBarI2cDevice* instance(const char* deviceName, uint8_t addr);
    bool boot(const char* serviceName);
    void unboot(const char* serviceName);

    // I2C 设备通常无需重写 initI2c()，基类默认指向 EASYB.i2c0

   protected:
    static constexpr bool _MULTI_INSTANCE = false;
};
```

**3. 写实现文件**（`src/device/i2c/Foo.Bar.i2c.device.cpp`）：

```cpp
#include "core/base/DeviceBase.i2c.cpp"    // ⚠ 第一行：模板实例化，必须最先
#include "Foo.Bar.i2c.device.h"
#include "core/EasyBoard.h"                // EasyBoard 只在 .cpp 中 include

FooBarI2cDevice* FooBarI2cDevice::instance(const char* deviceName, uint8_t addr) {
    static FooBarI2cDevice inst;
    inst.deviceName = deviceName;
    inst.i2cAddr    = addr;
    return &inst;
}

bool FooBarI2cDevice::boot(const char* serviceName) {
    if (!DeviceI2cBase::boot(serviceName)) return false;  // 非首个持有者，跳过
    // 硬件初始化逻辑...
    return true;
}

void FooBarI2cDevice::unboot(const char* serviceName) {
    DeviceI2cBase::unboot(serviceName);
    if (this->bootServices.empty()) { /* 释放硬件 */ }
}
```

**4. 挂载到 EasyBoard**（`core/EasyBoard.h`）：

```cpp
#include "device/i2c/Foo.Bar.i2c.device.h"

struct {
    FooBarI2cDevice* fooBar = FooBarI2cDevice::instance("Foo.Bar", 0x1A);
} devicesI2c;
```

GPIO 设备还需在 `EasyBoard::onboardDeviceGpio()` 中调用 `setEasyBoard(this)`。

各总线差异详见下文。
