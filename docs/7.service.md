# 7. Rtos服务

服务是业务逻辑的载体。每个服务 = 一个 `RtosBase` 子类 = 一个独立的 FreeRTOS task。服务负责在合适的生命周期节点 boot/unboot 设备，并在 `_rtosLoop` 中编排设备操作。

## 7.1 服务基类：RtosBase

### 属性

| 属性 | 类型 | 说明 |
|---|---|---|
| `serviceName` | `const char*` | 服务名，同时作为 boot/unboot 的持有者标识 |
| `rtosStackSize` | `uint32_t` | task 栈大小（byte），默认 4096 |
| `rtosTaskDelayMs` | `uint32_t` | 每轮 `_rtosLoop` 之间的间隔（ms），默认 10 |
| `rtosTaskName` | `const char*` | FreeRTOS task 名称 |
| `_rtosRunning` | `bool` | 运行状态，`rtosRun()` 置 true，`rtosStop()` 或 task 退出置 false |

### 公开方法

| 方法 | 说明 |
|---|---|
| `rtosRun()` | 启动服务：`initRtos()` → `_rtosBegin()` → `xTaskCreate` |
| `rtosStop()` | 停止服务：调 `_rtosEnd()` 并置 `_rtosRunning = false` |
| `serviceDelay(uint32_t ms)` | task 内延迟，先调 `_delayHook(ms)` 再 `vTaskDelay` |

### 子类覆写的钩子

| 钩子 | 说明 |
|---|---|
| `initRtos()` | 设置 task 名、栈大小、循环间隔（纯虚） |
| `_rtosBegin()` | 主线程执行：boot 设备、申请资源（**禁止 vTaskDelay**） |
| `_rtosBeforeLoopOnce()` | task 上下文，只跑一次，可做预热/演示 |
| `_rtosLoop()` | 周期业务，框架在每轮之间自动 `vTaskDelay(rtosTaskDelayMs)` |
| `_rtosEnd()` | 清理：unboot 设备、释放资源（需保证幂等） |
| `_delayHook(uint32_t ms)` | `serviceDelay` 中 vTaskDelay 之前调用（LVGL 服务覆写为 `lv_tick_inc`） |

## 7.2 生命周期（完整流程）

```
rtosRun()                              // 调用者线程（通常是 main 线程）
  ├─ initRtos()                        // 子类设置 task 属性
  ├─ 已在运行？→ 打 [WARN]，直接返回
  ├─ _rtosBegin()                      // ⚠ 主线程上下文，task 尚未创建
  │                                     禁止 vTaskDelay，只能做同步初始化
  ├─ _rtosRunning = true
  └─ xTaskCreate(_rtosTask, ...)       // 创建 FreeRTOS task，优先级 1

_rtosTask(self)                        // 新 task 上下文
  ├─ _rtosBeforeLoopOnce()             // 只跑一次，可以 serviceDelay
  ├─ while(_rtosRunning) {
  │     _rtosLoop()                    // 周期业务
  │     vTaskDelay(rtosTaskDelayMs)    // 框架自动 delay
  │  }
  ├─ _rtosEnd()                        // 清理：unboot 设备
  └─ vTaskDelete(nullptr)
```

> `_rtosEnd()` 在 `rtosStop()` 路径下会被**执行两次**（调用者线程一次 + task 退出时一次），需保证幂等。

## 7.3 serviceDelay 与 _delayHook

所有 task 内的延迟统一用 `serviceDelay(ms)` 而非裸 `vTaskDelay`：

```cpp
void serviceDelay(uint32_t ms) {
    this->_delayHook(ms);      // 默认空，LVGL 服务覆写为 lv_tick_inc
    vTaskDelay(pdMS_TO_TICKS(ms));
}
```

如果服务涉及 LVGL（如 DisplayServiceRtos），**必须覆写** `_delayHook` 为 `lv_tick_inc(ms)`，否则 LVGL 时基停走，动画冻结。

## 7.4 设备共享

多服务可以 boot 同一设备。框架按 `serviceName` 引用计数：

```cpp
// Service A 的 _rtosBegin
EASYB.devicesGpio.mic->boot(this->serviceName);   // 首个持有者 → 硬件初始化

// Service B 的 _rtosBegin
EASYB.devicesGpio.mic->boot(this->serviceName);   // 引用计数 +1，不重复初始化

// 各自的 _rtosEnd
EASYB.devicesGpio.mic->unboot(this->serviceName); // 分别减少计数
// 最后一个 unboot 才释放硬件
```

共享设备时注意：采样率等参数需在首个 boot 之前设置一致。

> ⚠ **注意**：服务 **.h** 只 include `RtosBase.h`，**不 include `EasyBoard.h`**。  
> `EasyBoard.h` 只在 **.cpp** 中 include。保持这个习惯即可避免 `EasyBoard ↔ Service` 的循环依赖。

## 7.5 新增服务的步骤

1. 写头文件：继承 `RtosBase`，设置 `serviceName`，覆写 `initRtos()`
2. 写实现文件：实现 `_rtosBegin` / `_rtosLoop` / `_rtosEnd`
3. 在 `EasyBoard.h` 的 `servicesRtos` struct 中加值成员
4. 在 `main.cpp` 中调用 `EASYB.servicesRtos.xxx.rtosRun()`

### 7.5.1 最小服务模板

```cpp
// Foo.service.rtos.h
class FooServiceRtos : public RtosBase {
   public:
    const char* serviceName = "foo";
    void initRtos() override {
        this->rtosTaskName    = this->serviceName;
        this->rtosStackSize   = 4096;       // 用 LVGL/音频 则给 8192
        this->rtosTaskDelayMs = 20;
    }
   private:
    void _rtosBegin() override;
    void _rtosLoop()  override;
    void _rtosEnd()   override;
};

// Foo.service.rtos.cpp
void FooServiceRtos::_rtosBegin() {
    // boot 设备
}
void FooServiceRtos::_rtosLoop() {
    // 周期业务
}
void FooServiceRtos::_rtosEnd() {
    // unboot 设备
}
```
