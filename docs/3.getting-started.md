# 3. 开始使用

## 3.1 了解你的硬件

打开 `src/config/pinGpios.config.h`，所有 GPIO 引脚在此统一定义：

```cpp
#define PIN_GPIO_LCD_NV3007_CS  GPIO_NUM_5
#define PIN_GPIO_I2C_SDA        GPIO_NUM_41
// ...
```

每个宏对应一个外设信号。未接线的外设设为 `GPIO_NUM_NC`，框架自动跳过。

引脚宏定义后，还需在对应的设备子类中通过 `PIN_GPIOS` 声明该设备实际使用哪些引脚。以 LCD 为例，`LcdNv3007Device` 内部声明了：

```cpp
struct Pins {
    PinDef cs  {"Lcd.NV3007.CS",  PIN_GPIO_LCD_NV3007_CS};
    PinDef dc  {"Lcd.NV3007.DC",  PIN_GPIO_LCD_NV3007_DC};
    PinDef rst {"Lcd.NV3007.RST", PIN_GPIO_LCD_NV3007_RST};
    PinDef* begin() { return &cs; }
    PinDef* end()   { return &rst + 1; }
} PIN_GPIOS;
```

这样基类 boot 时才能自动遍历并注册引脚。新增设备时也遵循这个模式，详见「六、设备」章节。

## 3.2 选择要启用的服务

打开 `src/main.cpp`，选择需要的服务启用rtosRun()即可。

```cpp
void setup() {
    EASYB.init();

    // EASYB.servicesRtos.connectivityServiceRtos.rtosRun();  // WiFi AP
    EASYB.servicesRtos.motionServiceRtos.rtosRun();           // 电机测试
    EASYB.servicesRtos.displayServiceRtos.rtosRun();          // LVGL 显示
}
```

## 3.3 编译 & 烧录

```bash
# 编译 + 烧录固件
pio run -t upload

# 如果修改了 data/ 下的文件（GIF、前端），还需烧录文件系统
pio run -t uploadfs
```

## 3.4 查看串口日志

```bash
pio device monitor
```

波特率 115200。正常启动会看到：

```
[EasyBoard] Wire.begin(SDA=41, SCL=42)
[EasyBoard] HSPI begin(SCK=2, MOSI=1)
=== GPIO Allocations ===
  GPIO 48 -> NeoPixel
  ...
```

## 3.5 确认引脚占用

在日志中找到 `[GPIO] CONFLICT` 即表示有引脚冲突。修改 `pinGpios.config.h` 后重新编译烧录即可。
